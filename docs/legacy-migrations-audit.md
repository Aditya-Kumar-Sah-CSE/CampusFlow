**Audit Date:** 2026-09-30  
**Target Directory:** `supabase/migrations_legacy_bce`  
**Active Production Directory:** `supabase/migrations` (Untouched)

## Executive Summary

An exhaustive audit of all 13 migration files within `supabase/migrations_legacy_bce` was conducted against the current application codebase (`src/`, `scripts/`, `package.json`, `docs/`), the active multi-tenant migrations (`supabase/migrations/`), and the live production Supabase database.

### Key Audit Findings:
1. **Live Database Presence:** Direct inspection of the live production database confirmed that physical objects defined across these migrations (`academic_years`, `branches`, `semesters`, `faculties`, `subjects`, `faculty_subject_assignments`, `feedback_forms`, `feedback_form_items`, `feedback_response_records`, `billing_plans`, `payment_settings`, `audit_logs`, `admin_billing_accounts`, `payment_requests`, `admin_requests`, `admin_trial_entitlements`, `google_oauth_tokens`, `admins`) physically exist in the production database schema.
2. **Active Production Dependencies:** Core application tables such as `feedback_forms` (and its Google integration columns), `feedback_form_items`, `feedback_response_records`, `billing_plans`, `payment_settings`, and the `payment-proofs` storage bucket were originally created by these legacy migrations and continue to hold live production data and support active runtime features.
3. **Migration Lineage & Safety:** Per the mandated safety invariants, no migration file may be deleted if it created objects still in use, or represents applied production migration history. Any file whose standalone production history cannot be decoupled without risk must be retained.

1.
